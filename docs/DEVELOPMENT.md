# Сборка и устройство проекта

## Требования

- JDK 17.
- Android SDK Platform 36, Build Tools 36.0.0.
- Gradle 8.11.1 (wrapper) и Android Gradle Plugin 8.10.1.
- Node.js 20+ для тестов JavaScript.

Укажите Android SDK через `ANDROID_HOME` или `local.properties`:

```properties
sdk.dir=/absolute/path/to/Android/sdk
```

## Сборка

```sh
./gradlew :android:assembleDebug
./gradlew :android:testReleaseUnitTest :android:assembleRelease :android:lintRelease
```

Windows: используйте `gradlew.bat`. Первая сборка скачивает Gradle и зависимости из официальных репозиториев Google/Maven Central.

- Отладочный APK: `android/build/outputs/apk/debug/android-debug.apk`.
- Неподписанный release APK: `android/build/outputs/apk/release/android-release-unsigned.apk`.

Release APK необходимо подписать своим Android-ключом через `apksigner`. Официальные обновления в GitHub Releases подписываются исходным ключом проекта. Закрытый ключ и пароль в репозитории отсутствуют. Самостоятельно подписанный APK нельзя установить поверх версии, подписанной другим ключом. Не удаляйте установленную версию с нужными данными ради тестирования: используйте отдельное устройство или резервную копию.

ABI-разделение не включено: release собирается одним universal APK. Состав нативных библиотек следует перепроверять при обновлении ML Kit.

## Проверки

```sh
npm install
npm test
./gradlew :android:testReleaseUnitTest :android:lintRelease
```

33 проверки JavaScript: 15 тестов движка и 18 интеграционных DOM-тестов. В DOM-тестах Android-службы заменены явными заглушками: они проверяют протокол, а не работу физического стилуса, голоса или MAX.

Проверяются разбор и обновление наборов, сохранение прогресса, награды и дневной предел, подсказки, повторение ошибок, выбор наборов, PIN, импорт/экспорт, копилка, восстановление и отказ сохранения. Рукописный ввод проверяется на отсутствие автоматического оценивания, передачу видимого задания без английского ответа и воспроизведение диктанта из окна письма, редактирование результата и отклонение запоздалых ответов.

Дополнительно выполняются два JVM-теста Android: построение контекста отдельного слова с настоящей библиотекой ML Kit и отклонение неизмеренного поля. Это проверяет ошибку `Missing required properties: preContext`, вызывавшую вылет в 1.3.

## Основные файлы

| Файл | Назначение |
|---|---|
| `android/assets/engine.js` | Наборы, очередь упражнений, сравнение ответов, прогресс и копилка |
| `android/assets/app.js` | Экраны и взаимодействие с Android-мостом |
| `android/assets/style.css` | Лавандовое оформление |
| `android/src/ru/mayusha/words/MainActivity.java` | WebView, хранение, PIN, голос, импорт и экспорт |
| `android/src/ru/mayusha/words/HandwritingDialog.java` | Независимое поле штрихов, загрузка модели, ML Kit и выбор результата |
| `android/src/ru/mayusha/words/ShareProvider.java` | Временный доступ только для чтения к экспортированным наборам |
| `tests/` | Тесты учебной логики и DOM |

## Рукописное распознавание

Нативное поле принимает координаты и время штрихов пальца/стилуса. Модель `en-US` загружается через `RemoteModelManager`. API 19.0.0 использует классы `com.google.mlkit.vision.digitalink.recognition` и результаты из `com.google.mlkit.vision.digitalink.common`.

Распознаватель не получает правильное слово задания. До трёх вариантов показываются пользователю. Выбор переносит текст в обычное поле, не засчитывая ответ. Изменение штрихов инвалидирует старые результаты. Закрытие окна или смена задания не позволяет позднему результату перезаписать новый ответ. Ввод с Gboard продолжает работать.

## Проверка на телефоне

1. Установить APK поверх предыдущей версии и проверить сохранность наборов, имени, PIN и копилки.
2. Оставить Gboard, открыть «Написать рукой», скачать модель и написать слово пальцем/S Pen.
3. Проверить отмену штриха, очистку, несколько вариантов, исправление перенесённого текста и отсутствие начислений до «Проверить».
4. После загрузки модели отключить интернет и повторить распознавание.
5. Проверить закрытие окна во время загрузки/распознавания, возврат в задание и смену ориентации.
6. Проверить английский голос, импорт `.maywords`, отправку через MAX и повторную просьбу без второго списания.

Браузерные скриншоты отражают интерфейс WebView, но не нативное окно ML Kit. До испытания на физическом устройстве нельзя считать качество распознавания конкретного детского почерка подтверждённым.
